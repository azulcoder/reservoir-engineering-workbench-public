# Case A1 protocol -- volumetric baseline

Pre-registered. Every threshold in section 6 was fixed from the analysis in sections 4
and 5 before `run.py` was executed for the first time. Any later amendment is recorded
in the change log at the end of this file with its reason.

## 1. Engineering question and decision

On data generated by the volumetric gas material balance with no measurement error,
does the p/Z inverse recover the gas in place to the precision the arithmetic allows,
and what does that establish?

The decision this supports is narrow and it is about the code, not about a reservoir.
Before any p/Z estimate from this repository is quoted anywhere else, the estimator has
to be shown to be exact on a problem whose answer is known, so that a later discrepancy
on a harder problem can be attributed to the physics being studied rather than to the
arithmetic. A recovery error of a few parts in `1e12` says the implementation is sound.
A recovery error of a few parts in `1e3` would say the implementation has a defect, and
every case built on it would have to stop until that was found.

What would disprove the favoured interpretation: any recovery error above the
floating-point budget in section 5 on the noise-free constant-Z problem. There is no
statistical explanation available for that case. The data are exactly collinear by
construction, so a straight-line fit either passes through them or the code is wrong.

## 2. Sources and model identity

No external data. Everything is generated inside the run.

| Item | Value |
|---|---|
| Forward generator | `reservoir_lab.depletion.simulate_volumetric_depletion` |
| Inverse estimator | `reservoir_lab.material_balance.fit_pz_depletion` (OLS, unweighted) |
| Gas properties | `reservoir_lab.gas_properties.pseudocritical_sutton`, `z_factor` with `method="dak"` |
| Provenance | `reservoir_lab.provenance.RunRecord` |
| Units | Field units, absolute pressure and absolute temperature, per `docs/api_contract.md` C1 |
| Standard basis | `units.SPE_STANDARD`: 14.696 psia, 60 degF, `Z_sc = 1.0` |

**Why the recovery is not tautological.** `depletion` and `material_balance` are
separate modules and share no code. The generator does not call the estimator and both
are not built on a shared "the balance is this expression" helper. The generator solves,
at each step, the implicit problem `p/Z(p) = (p_i/Z_i)(1 - G_p/G)` for `p` with a
bracketed safeguarded Newton iteration, and reports `p` and `Z(p)` separately. The
estimator never sees `G`; it sees `(G_p, p/Z)` pairs and fits a straight line whose
x-intercept it reports. A coding slip on one side therefore does not cancel against the
other. That is all the separation buys, and it is narrower than it sounds: section 3 shows
the standard-condition group and the reservoir temperature cancel identically out of the
balance, so an error in either is invisible to this comparison however large it is, and
diagnostic D1 in section 4.5 measures that blindness rather than leaving it as an
argument. The independent oracle in section 3 removes least squares from the comparison
entirely for the noise-free cases.

That argument has a limit and it is stated here rather than in the report's small print:
the two modules share the *physical assumption set*. Both assume a single tank of
constant hydrocarbon pore volume, dry gas of fixed composition, isothermal depletion, no
influx, no injection and one declared standard basis. Agreement between them therefore
verifies arithmetic and cannot validate the assumption set. Case A1 makes no claim about
any reservoir.

## 3. Governing model and independent reference answer

The inventory balance for a closed tank of constant hydrocarbon pore volume, with
`B_g = (p_sc / (T_sc Z_sc)) Z T / p`:

    (G - G_p) B_g(p) = G B_g(p_i)      =>      p/Z = (p_i/Z_i) (1 - G_p/G)

The standard-condition group and the reservoir temperature cancel identically, so the
p/Z form is exact for *any* deviation-factor behaviour, not only for a constant Z. This
matters for experiment 2 and is the reason its predeclared expectation in section 6 is
not the one a reader might assume; see section 4.2.

**Independent reference answer.** For an exactly collinear series, two distinct points
determine the line and therefore the x-intercept, with no least squares involved:

    G_two_point = x_1 + y_1 (x_2 - x_1) / (y_1 - y_2)

Computed in `run.py` from the first and last observation only. For the noise-free
experiments this is an oracle that is independent of `regression.ols_line`,
`regression.x_intercept` and of every sum the estimator forms. It must agree with the
estimator's x-intercept and with the generator's declared `G`.

For the noisy experiments the reference is the classical inverse-prediction variance,

    Var(G_hat) = (s^2 / b^2) [ 1/n + (G_hat - xbar)^2 / S_xx ]

coded directly in `run.py` with `math.fsum` over the raw series. This is an independently
written implementation, not an independent formula: it is the same expression the library
collapses to. It is reported as a cross-check on the library's general delta-method path
(which retains the slope-intercept covariance term and also serves Deming and York fits),
not as external truth. The genuinely independent check on the reported standard error is
the Monte Carlo spread in experiment 3.

## 4. Experiments

One fixed design is used throughout so that the four experiments differ in one factor
each.

| Parameter | Value | Note |
|---|---|---|
| `G` | 1.0e11 scf | 100 Bscf |
| `p_i` | 4000.0 psia | absolute |
| `T` | 640.0 degR | 180.3 degF, isothermal |
| observations | 11 | `t = 0, 200, ..., 2000` d |
| gas rate | 2.5e7 scf/d, constant | so `G_p,i = i * 5e9` scf exactly |
| final depletion | 0.500 of `G` | exact by construction |
| `minimum_pressure_psia` | 200.0 | see below |
| `solver_tolerance` | 1.0e-12 | library default |

The pressure floor is set to 200 psia rather than to the 14.696 psia default because the
generator scans p/Z over `[floor, p_i]` to check monotonicity, and at 14.696 psia the
Dranchuk-Abou-Kassem reduced pressure is 0.022, far outside the correlation's published
window of `[0.2, 30.0]`. At 200 psia the reduced pressure is 0.298 and every evaluation
in the run is inside the published window. Evaluating a correlation outside its window
and then quoting the answer to twelve figures would be incoherent.

The abscissa is evenly spaced with `x_i = i * fG/10`, so `xbar = fG/2` and
`S_xx = 1.1 f^2 G^2` exactly, where `f` is the observed depletion fraction. Both are
used in section 5.

### 4.1 Experiment 1 -- noise-free recovery with constant Z

`z_of_pressure` returns 0.900 at every pressure, so `p_i/Z_i = 4444.444 psia` and the
p/Z line is exactly straight. `NoiseModel` is exactly zero on all four channels. Fit all
11 points by unweighted OLS and compare the x-intercept with `G`.

### 4.2 Experiment 2 -- pressure-dependent Z

Same design, with `z_of_pressure` the Dranchuk-Abou-Kassem deviation factor at 640 degR
for a 0.65 specific-gravity gas on Sutton pseudocriticals. Two fits:

**2a, consistent Z.** Ordinate `p/Z(p)` from the generator's own reported pressures and
deviation factors. The pre-registered expectation here is *exact recovery again*, and it
is the opposite of what the case brief anticipated. The brief expected the p/Z line to
be curved and the recovered G to carry a curvature bias. It does not and it will not: the
balance in section 3 is linear in `G_p` for any `Z(p)` whatever, because the whole
standard-condition group cancels. Curvature lives in `p` against `G_p`, which is why the
p/Z plot exists. Predicting a bias here and then finding none would be a failure to check
the proposal against first principles, so the prediction is recorded the other way round
and the report will state whichever way it comes out. Quantity to report: the
non-linearity of the *pressure* series, as the maximum absolute deviation of `p` from the
straight line through its endpoints, expressed as a fraction of `p_i`. That is the real
curvature and it is a number worth having.

**2b, inconsistent Z -- the mechanism that does bias G.** The same generated pressures
fitted against an ordinate formed with a constant `Z = Z_i` throughout, which is what an
analyst does who takes the initial deviation factor off a chart and reuses it. This is
the often-ignored effect the brief was pointing at, and it is a real one. Z at 4000 psia
on this trend is 0.9322 and falls to about 0.884 near the last observation, so `p/Z_i`
understates the true `p/Z` by an amount that grows with depletion, tilting the fitted
line steeper and pulling the x-intercept in. The predicted sign is therefore an
**underestimate**. A two-point estimate through the endpoints of that distorted ordinate
gives about -4.9 percent, so the band predeclared in section 6 is 1 to 10 percent. The Z
trend was tabulated before the experiment was run; it is an input to the study, not a
result of it.

### 4.3 Experiment 3 -- is the reported standard error meaningful

Constant `Z = 0.900`, `pressure_sigma_psia = 5.0`, all other noise channels zero. One
thousand realisations, seeds 1000 to 1999, each generated and fitted independently.
Compare the Monte Carlo spread of `G_hat` against the mean of the standard errors the
estimator reported, and check the coverage of the two-sided 95 percent Student-t
interval on nine degrees of freedom.

### 4.4 Experiment 4 -- what the x-intercept extrapolation costs

Two fits with identical noise: `pressure_sigma_psia = 5.0`, one fixed seed, 11 points in
both, constant `Z = 0.900`. The only difference is the observed depletion fraction.

* 50 percent case: `t = 0, 200, ..., 2000` d, as in experiment 1.
* 10 percent case: `t = 0, 40, ..., 400` d, same rate, so `G_p,i = i * 1e9` scf.

The noise is identical point for point, not merely identically distributed: the generator
draws one variate per point per channel from a local `random.Random(seed)` in a fixed
order, both cases have 11 points and the same seed, the perturbation is additive in psia,
and Z is constant, so the perturbation of the ordinate is the same eleven numbers in both.

### 4.5 Post-hoc diagnostics, added after run-005

Neither of these was pre-registered. They were added in response to a referee reading of
`report.md`, they are recorded here so the distinction survives, and neither is gated:
no acceptance threshold in section 6 changed, and every experiment payload in run-006's
`summary.json` is bit-identical to run-005's.

**D1, seeded defects.** Experiments 1 and 2a report a recovery error of zero, which is
evidence of correctness only for defects this design can see, and nothing above established
which those are. D1 seeds known defects into the experiment-1 arm -- a corrupted
standard-volume basis, a changed reservoir temperature, a rescaled ordinate, a rescaled
abscissa, a single displaced point -- and reports the recovery error each produces, plus
the smallest magnitude of each class that the A1 gate of `5.0e-12` would catch.

**D2, the sign of the frozen-`Z_i` bias.** Section 4.2 predicts the sign of experiment 2b
for the window at `p_i = 4000` psia, and `report.md` originally generalised that sign to
the mechanism. D2 tests the generalisation inside the case's own machinery by moving the
depletion window across the minimum of `Z(p)`, sweeping `p_i` from 4000 down to 1000 psia
at 50 percent depletion and the depletion fraction from 0.5 to 0.9 at 4000 psia.

## 5. Error budget and the analytic predictions

### 5.1 Conditioning of the extrapolation

The fitted line evaluated at the x-intercept is `c . y` with
`c_i = 1/n + (x_0 - xbar)(x_i - xbar)/S_xx`, so `||c||_2 = sqrt(h)` with

    h(f) = 1/n + (x_0 - xbar)^2 / S_xx = 1/11 + (1 - f/2)^2 / (1.1 f^2)

for the design in section 4. A perturbation `dy` of the ordinate moves the fitted value
at `x_0` by at most `sqrt(h) ||dy||_2`, and the x-intercept by that divided by the slope
magnitude. Since `|slope| * G = p_i/Z_i`, the relative error in the recovered gas in
place is bounded by

    |dG/G| <= sqrt(h n) * max_i |dy_i| / (p_i/Z_i)

| Depletion `f` | `h(f)` | `sqrt(h)` | `sqrt(h n)` |
|---|---|---|---|
| 0.50 | 2.136364 | 1.461630 | 4.847680 |
| 0.10 | 82.136364 | 9.062912 | 30.058277 |

This is the condition number of the extrapolation. It is small at half depletion because
the intercept sits only 1.5 data-spans beyond the last point, and it is an order of
magnitude larger at a tenth, where the intercept sits nine data-spans out.

### 5.2 Predicted tolerance, experiment 1

Two terms.

*Generator.* `safeguarded_newton` returns when the bracket width falls below
`tolerance * max(1, |x|)`, so the returned pressure satisfies `|dp| <= 1e-12 p`. With Z
constant, `|d(p/Z)| <= 1e-12 (p/Z) <= 1e-12 (p_i/Z_i)`. Amplified:
`4.847680 * 1e-12 = 4.85e-12`.

*Arithmetic.* The least-squares sums run over 11 terms, so the relative rounding of the
ordinate scale is of order `10 * eps = 2.2e-15`; amplified, `1.1e-14`. The final division
`-b/m` adds a couple of ulps.

Budget `4.86e-12`. **Predeclared acceptance: `|G_hat/G - 1| <= 5.0e-12`.**

The bracket bound is a guarantee, not an expectation. The step solver warm-starts from
`required_p_over_z(p_prev) * Z(p_prev)`, which for constant Z is the exact root at the
first residual evaluation, so a realised error of order `1e-15` would not be surprising.
That is an expectation about the realisation. The gate is the guarantee, because a gate
set from an expectation is a gate set from a rehearsal.

### 5.3 Predicted tolerance, experiment 2a

Same structure, two extra factors.

*Sensitivity of p/Z to the solver's pressure error.* `d(p/Z)/dp * p / (p/Z) = 1 - (p/Z) Z'`.
From the tabulated trend, `|Z'| <= 5.1e-5` per psi over 4000 to 1900 psia and `p/Z <= 4300`
psia, so the factor is bounded by 1.25.

*Inner solve for Z.* `z_factor_dak` iterates on reduced density to a tolerance of `1e-12`,
contributing a further relative error of order `1e-12` in Z and therefore in `p/Z`.

Budget `1.25 * 4.85e-12 + 4.85e-12 + 1.1e-14 = 1.09e-11`.
**Predeclared acceptance: `|G_hat/G - 1| <= 2.0e-11`**, a factor of two of margin over the
budget for terms of the same order that this arithmetic does not resolve.

### 5.4 Predicted calibration, experiment 3

With `sigma = 5` psia on pressure and `Z = 0.9`, the ordinate noise is `s = 5.5556` psia,
`|slope| = 4.444444e-8` psia/scf, and

    SE(G_hat) = (s / |slope|) sqrt(h(0.5)) = 1.827038e8 scf = 0.18270 percent of G

The Fieller discriminant is `g = (t_{0.975,9} SE(slope) / slope)^2 = 2.9e-5`, so the
linearisation behind the delta method is far from its failure edge and the symmetric
interval is a faithful summary. The estimator uses the sample residual standard deviation,
whose expectation is `c4(9) sigma = 0.9727 sigma`, so the mean reported SE should sit about
2.7 percent *below* the analytic value while the Monte Carlo spread should match it. The
expected ratio of spread to mean reported SE is therefore about 1.028, not 1.000, and the
gate is set around 1.028 rather than around 1. With 1000 realisations the Monte Carlo
standard error of a standard deviation is `1/sqrt(2N) = 2.2` percent.

### 5.5 Predicted ratio, experiment 4

The hat matrix of a straight-line fit depends on the abscissa only through the column
space of `[1, x]`, which a scale change does not alter, and the deterministic part of the
ordinate is exactly linear in both cases, so it is annihilated. The residual vector is
therefore *identical* in the two fits, and so is `s`. The slopes differ only through the
noise term, whose standard deviation scales as `1/f`, which is about 1.1 percent of the
slope at `f = 0.1` for this sigma. Hence

    SE_10 / SE_50 = sqrt(h(0.1)) / sqrt(h(0.5)) * |slope_50| / |slope_10| = 6.2005 * (1 +- 0.015)

**Predeclared acceptance: the realised ratio of reported standard errors is within 5
percent of 6.2005.**

The ratio of the *point-estimate* errors is deliberately not gated. It is
`c^(10) . e / (c^(50) . e)` for one particular noise vector, not a ratio of norms, and
because the `1/n` term enters the two `c` vectors identically rather than proportionally
it need not equal 6.2005. Its expected size is nearer `0.95/(11 * 0.1) / (0.75/(11 * 0.5))
= 6.33` when the mean of the noise happens to be small. It is reported and explained, not
gated.

## 6. Acceptance criteria, fixed in advance

| # | Criterion | Threshold |
|---|---|---|
| A1 | Experiment 1 relative recovery error | `<= 5.0e-12` |
| A2 | Experiment 1 two-point oracle agrees with the OLS x-intercept | relative difference `<= 5.0e-12` |
| A3 | Experiment 2a relative recovery error, consistent Z | `<= 2.0e-11` |
| A4 | Experiment 2b bias from a constant `Z_i` ordinate | negative, magnitude between 1 and 10 percent |
| A5 | Experiment 3 spread over mean reported SE | in `[0.90, 1.15]` |
| A6 | Experiment 3 mean relative bias of `G_hat` | `|mean(G_hat)/G - 1| <= 5.0e-4` |
| A7 | Experiment 3 coverage of the 95 percent Student-t interval | in `[0.92, 0.97]` |
| A8 | Experiment 3 mean reported SE over the analytic SE | in `[0.95, 1.00]` |
| A9 | Experiment 4 ratio of reported standard errors | `|ratio/6.2005 - 1| <= 0.05` |
| A10 | Determinism: two runs with the same config give byte-identical `summary.json` | exact |

A5 is centred on 1.028 and not on 1.0 for the reason given in 5.4. A8's upper bound is
1.00 because the `c4` correction is one-sided: an estimator whose mean reported SE
*exceeded* the analytic value would be reporting an inflated uncertainty, which is the
failure mode `api_contract.md` C6 says the covariance term exists to prevent, and it
would be a finding.

**Which of these thresholds section 5 actually derives.** A1, A2, A3, A5 and A8 come from
the budgets in 5.2, 5.3 and 5.4. Three do not, and saying so is part of the audit trail
rather than a later softening. None of them is changed here; a threshold moved after a
result is not a threshold.

* **A9.** Section 5.5 derives `6.2005 * (1 +- 0.015)` and the gate was written at `+- 5`
  percent. The widening by a factor of 3.3 has no derivation anywhere in this document. The
  realised departure, `-3.38` percent, falls outside the derived band and inside the
  written gate, so A9 passed on a threshold its own analysis does not support and must be
  read as a regression pin on the ratio rather than as a predeclared gate. The account of
  the departure -- leverage evaluated at the fitted x-intercept instead of at the true G --
  came later still, as a run-003 diagnostic, and is a post-hoc explanation of a prediction
  that missed.
* **A6 and A7** appear only in the table above and are derived in no section. A6 at
  `5.0e-4` is seventeen times looser than the realised `2.95e-05`. A7's band is close to
  three binomial standard errors either side of the nominal 0.95, `sqrt(0.95 * 0.05 / 1000)
  = 0.0069`, but rounded asymmetrically and with no reason given at the time. Neither looks
  reverse-engineered from an answer; neither was derived in advance.
* **A10** is not self-checked by `run.py`. `summary.json`'s `criteria` block holds A1 to A9
  only, because a single execution cannot test determinism. A10 rests on a manual `cmp`
  between run directories on one machine, and the criteria table in `report.md` says so.

## 7. Chronological holdout

None, deliberately. A holdout answers whether a fitted model predicts observations it was
not fitted to. This case asks whether an estimator inverts a known forward map, which a
holdout cannot address: the generator's future points lie on the same exact line as the
fitted ones, so a holdout here would report the same near-machine-precision agreement
twice and would read as a second, independent piece of evidence when it is not. Stage A's
holdout obligation belongs to the cases that fit a model whose structure is in doubt.

## 8. What would make this case inconclusive

* **The generator's own numerical error is not resolvable below the effect being
  measured.** If `max |residual_p_over_z_psia|` from experiment 1 is not at least two
  orders of magnitude below `5.0e-12 * (p_i/Z_i)`, the recovery error cannot be
  attributed to the estimator rather than to the generator's root finder, and A1 becomes
  untestable rather than passed or failed.
* **The Monte Carlo in experiment 3 is not converged.** If the spread-to-SE ratio lands
  outside `[0.90, 1.15]` by less than two Monte Carlo standard errors (4.4 percent), the
  result is inconclusive rather than a failure, and the correct response is more
  realisations, not a wider gate.
* **`fit_pz_depletion` raises `NotIdentifiableError` on any experiment-4 realisation.**
  At 10 percent depletion with this sigma the fitted G is about 1 percent uncertain, so
  this should not happen, but if it does the 10 percent arm has no estimate and the ratio
  in A9 does not exist. That is an inconclusive arm and is to be reported as one, with
  the failing realisation kept in the run record.
* **A2 fails while A1 passes.** That would mean the OLS path and the two-point oracle
  disagree on data that are exactly collinear, which is a defect somewhere in the
  regression module, and the whole case stops until it is found. It would not be reported
  as a successful recovery with a caveat.

## 9. What this case cannot establish

Stated here so it cannot be softened after the numbers arrive.

* It is numerical verification only, the first of the three evidence layers in PLAN.md
  section 1. It is not benchmark reproduction and it is not engineering validation.
* It says nothing about whether any reservoir has a constant hydrocarbon pore volume, no
  aquifer, no retrograde dropout or a representative volume-averaged pressure. The
  generator asserts all of those; it does not test them.
* Exact recovery here is compatible with the estimator being badly wrong on a reservoir
  that violates the volumetric assumption. The library's own docstring records a
  documented weak-water-drive case with R-squared 0.9998 and an 8 percent overestimate.
  Demonstrating that is case A2's job, not this one's.
* The Dranchuk-Abou-Kassem deviation factor used in experiment 2 is a correlation
  evaluated inside its published window. It is not a measured PVT report and nothing here
  validates it against one.
* No reserves terminology, no development decision and no operational limit follows from
  any number in this case.
